How to Bates number a PDF on a Mac

macOS has no built-in Bates numbering. Here is every option that actually exists, what each one can and cannot do, and how to choose without finding out the hard way.

The short version: if you have one document and you only need numbers on the pages, Preview will get you most of the way. If you have a production spread across several files and you need the numbering to run straight through them, you need a tool built for it. The difference between those two situations is where most problems come from.

Option 1 — Preview

Preview can print a document back to PDF with page numbers, and it can merge documents by dragging pages in the sidebar. For a single exhibit that needs plain numbering, that is often enough.

What it cannot do: add a prefix, pad numbers with leading zeros to a fixed width, start from an arbitrary number, or keep a sequence running across separate files. Those four things are what makes a number a Bates number rather than a page number, so Preview does not really do Bates numbering — it does page numbering, which is a different job.

Option 2 — Automator and Quartz filters

macOS ships with Quartz filters, and Automator can apply one to a folder of PDFs. People do build workflows this way.

The limitation is structural rather than cosmetic: a Quartz filter is applied to each file independently, so it has no memory of how many pages the previous file had. You can number every file, but each one starts over. Getting a continuous sequence means writing a script that counts pages first and passes a starting number to each file — at which point you are in option 3.

Option 3 — The command line

With qpdf, Ghostscript, or a Python script using a PDF library, you can do anything described on this page. If you are comfortable in a terminal and you produce documents rarely, this is a legitimate answer and it costs nothing.

Two cautions. First, the work is not the numbering itself — it is the edge cases: landscape pages, unusual page sizes, existing content near the corner, files that are scans rather than text. Second, a script produces numbered files but not a record of what you produced, and you will want that record later.

Option 4 — A dedicated app

Whatever you use, these are the things to check before you trust it with a real production:

  1. Does numbering continue across files? Load three files and confirm the second one does not start at 1. This is the question that matters most, and the one most tools fail.
  2. Can you set the prefix, the digit count and the starting number? You need all three, not two of them.
  3. Can you see the resulting range before you commit? Knowing you are about to write ACME000001–ACME000412 lets you catch a mistake before it becomes four hundred stamped pages.
  4. Does it leave the originals alone? Numbered copies should be written somewhere you choose. A tool that overwrites source files makes every mistake permanent.
  5. Does it keep a record? Ranges, file names, page counts. You will need it.
  6. Does it need an internet connection? Many web-based PDF tools upload your documents to a server. For client material under a protective order, that is often not acceptable — and frequently not permitted by the firm's own policies.

Test before you rely on it. Take three sample files, number them, and open the second one. If its first page reads ACME000001 instead of continuing from the first file, stop — that tool is not usable for productions.

The workflow, in order

  1. Assemble. Put the files in the folder they will be produced from, named and ordered as they should appear. Numbering follows the order, so fix the order first.
  2. Redact. Always before numbering, never after.
  3. Choose the prefix and the width. Six digits is a safe default. Decide once, at the start of the matter.
  4. Continue from the last number used. If this is the second production in the matter, it starts where the first one ended — not at 1.
  5. Number to a new folder. Originals untouched.
  6. Check. First page of the first file, last page of the last file, and a couple of pages in the middle. Look for stamps landing on content.
  7. Record it. Date, prefix, range, files, page counts.

What about the originals?

Keep them. A production is a snapshot: the numbered copies are what went out, the originals are what you had. If a question arises later about whether a produced page matches the source, you need both, plus the record that ties them together.

Some tools record a hash of each output file, which is a short fingerprint that changes if the file changes. That turns "these are the documents we produced" from a claim into something you can demonstrate.
