Bates numbering multiple PDFs without restarting at 1

A production is rarely one file. When it spans several, the Bates sequence has to run straight through all of them — and this is where most tools quietly fail.

What correct looks like

Three files, 412 pages between them, prefix ACME, six digits:

File Pages Range
contract-2021.pdf 146 ACME000001 – ACME000146
correspondence.pdf 188 ACME000147 – ACME000334
invoices.pdf 78 ACME000335 – ACME000412

Every number appears once. Cite ACME000200 in a deposition and there is exactly one page it can be.

What most tools do instead

File Pages Range produced
contract-2021.pdf 146 ACME000001 – ACME000146
correspondence.pdf 188 ACME000001 – ACME000188
invoices.pdf 78 ACME000001 – ACME000078

Now there are three pages called ACME000001, three called ACME000002, and so on. The identifier identifies nothing. A request for ACME000050 has three possible answers, and neither side can tell which one is meant.

Why it happens

It is not carelessness — it is how the tools are built.

Most PDF utilities process one file at a time. Point them at a folder and they do the same thing to each file independently. Applied to numbering, that means every file gets its own sequence, because the tool has no idea the other files exist. On macOS this is true of Quartz filters, of most Automator workflows, and of nearly every free single-file numbering app.

Numbering a production correctly requires something different: the tool has to count the pages of every file before stamping anything, then carry a running total from one file to the next. That is a small amount of extra logic and a very large difference in outcome.

The manual workaround, and why it fails

You can do it by hand: number file one from 1, note that it ended at 146, number file two starting from 147, and so on.

It works when nothing changes. In practice something always changes. A document gets pulled the day before the deadline. A file turns out to have two extra pages. Someone re-runs one file to fix a stamp position. Each of those means recalculating every starting number after it, by hand, under time pressure. The arithmetic is trivial and the error rate is not — and the error is invisible until someone cites a page that turns out to be two different pages.

The test, in two minutes: take three PDFs, number them, and open the second one. If its first page reads ACME000001, the tool restarts per file and cannot be used for productions.

When restarting is actually correct

There is one case where per-file numbering is what you want: when each file is a separate exhibit with its own identifier, and the numbering is internal to that exhibit. Then EX12-001, EX12-002 and so on is right, and the exhibit prefix carries the uniqueness.

The distinction is whether uniqueness lives in the number or in the prefix. In a document production it lives in the number, so the sequence must be continuous. Check which situation you are in before you start, because changing your mind afterwards means re-producing.

Continuing across productions, not just across files

The same problem appears one level up. Your first production ends at ACME000412. Six weeks later there is a supplemental production. It must begin at ACME000413 — never at 1, and never at a round number you guessed.

This is why a production register matters. It records, for each production, the date, the prefix, the range used, the files and their page counts. Without it you are reconstructing the last number used from memory or by opening old files, and overlapping two productions is a problem with no clean fix: the documents are already out.

What a register should hold

  • Date of the production
  • Prefix, digit width, first and last number used
  • Every file name, in order, with its page count and its range
  • Where the output was written
  • Optionally, a hash of each output file — a fingerprint that changes if the file changes, which lets you demonstrate later that a produced document is the one you produced

A checklist before you produce

  1. Files are in the folder, named and ordered as they should be numbered.
  2. Redaction is done. Numbering comes after, always.
  3. Prefix and digit width match the rest of the matter.
  4. Starting number continues from the last one used, checked against the register rather than remembered.
  5. You can see the resulting range before committing — and it looks right.
  6. Output goes to a new folder; originals untouched.
  7. After the run: check the first page of the first file, the last page of the last file, and the first page of each file in between. That last check is the one that catches a restart.
